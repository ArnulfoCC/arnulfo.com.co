4. Primeros pasos en programación

Material de apoyo de los días 12 a 16 del plan. Escrito para alguien que nunca ha escrito una línea de código. No hay conocimientos previos supuestos, salvo uno: que sabes usar Excel bien. Y ese es justamente el punto de partida.

1. El puente: ya programas, solo que arrastrando

La palabra "programar" suena a un mundo nuevo. No lo es tanto. Cada vez que armas una hoja de cálculo estás describiendo un procedimiento paso a paso para que la máquina lo ejecute. Eso es un programa. Lo único que cambia es que en Excel el procedimiento se construye con el mouse, y en Python se escribe con palabras.

Lo que haces en Excel Cómo se llama en programación Qué cambia
=B2*0,19 Expresión con variables En vez de B2 escribes un nombre: base * 0.19
=SI(B2>1000000;"Alto";"Bajo") Condicional (if / else) Igual, pero en varias líneas y legible
SI anidado de cuatro niveles Condicional anidado (if / elif / else) Aquí gana Python por goleada: el SI anidado se vuelve ilegible a partir del tercer nivel
Arrastrar una fórmula por 500 filas Ciclo (for) Escribes la operación una vez y le dices cuántas veces repetirla
BUSCARV / CONSULTAV Búsqueda en una estructura de datos En Python es un diccionario o un merge de tablas
Filtro con criterio Condición dentro de un ciclo Recorres los datos y te quedas con los que cumplen
CONTAR.SI Contador dentro de un ciclo if condición: contador = contador + 1
SUMAR.SI Acumulador dentro de un ciclo if condición: total = total + valor
Tabla dinámica Agrupar y agregar Recorres, agrupas por clave y aplicas suma o promedio a cada grupo
Una hoja con nombre Variable o archivo Un nombre que guarda un valor

Dos diferencias reales, y conviene decirlas de una vez:

  1. En Excel ves los datos; en código ves el procedimiento. Al principio se siente como trabajar a ciegas. Se pasa en unos días, y a cambio ganas algo que Excel no da: el procedimiento queda escrito, se lee, se corrige y se repite con otros datos sin rehacer nada.
  2. El computador hace exactamente lo que escribiste, no lo que querías escribir. Un error de una coma detiene todo. Eso no es un defecto: es lo que hace que el resultado sea confiable.

2. Qué es un algoritmo y para qué sirve el pseudocódigo

Un algoritmo es una secuencia finita y ordenada de pasos que resuelve un problema. Tiene tres partes: entrada (qué datos recibe), proceso (qué hace con ellos) y salida (qué entrega).

Tú escribes algoritmos todos los días, solo que en español y sin llamarlos así:

Para verificar si una póliza está vigente: tomo la fecha de vencimiento del amparo; la comparo con la fecha de corte; si la fecha de vencimiento es anterior, la póliza está vencida; si no, está vigente.

Ese párrafo ya es un algoritmo. El pseudocódigo es ese mismo párrafo escrito con una estructura fija, para que no quede ambiguo. No es un lenguaje de programación: es un lenguaje intermedio entre tu cabeza y el código.

¿Y para qué sirve, si al final hay que escribirlo en Python? Para separar los dos problemas. Cuando programas sin pseudocódigo estás resolviendo al mismo tiempo qué hacer y cómo escribirlo, y eso es exactamente lo que hace que un principiante se bloquee frente a la pantalla en blanco. Con pseudocódigo, primero decides qué hacer (en español, sin sintaxis que falle) y después lo traduces. La materia Pensamiento Algorítmico se llama así precisamente porque evalúa la primera parte, no la segunda.

Todo pseudocódigo de este material tiene su equivalente en Python al lado. Léelos siempre en pareja.

3. PSeInt: el pseudocódigo que sí se ejecuta

PSeInt es un programa gratuito, muy liviano, hecho para aprender a programar en español. Escribes pseudocódigo y él lo ejecuta, te señala los errores y además genera el diagrama de flujo automáticamente. Es la herramienta estándar en cursos de Pensamiento Algorítmico en universidades hispanohablantes.

Cómo conseguirlo. Búscalo como "PSeInt" y descárgalo desde el sitio oficial del proyecto (está alojado en SourceForge desde hace años; no descargues versiones de portales de terceros). Hay versión para Windows, macOS y Linux. La instalación es siguiente-siguiente y ocupa poco espacio.

Configuración recomendada la primera vez. Al abrirlo, en el menú de configuración elige el perfil de lenguaje "Estricto". Es más exigente (obliga a declarar los tipos de variable), y esa exigencia es justamente lo que te prepara para Python.

Estructura mínima de un programa en PSeInt:

Algoritmo MiPrimerPrograma
    Escribir "Hola, este es mi primer algoritmo.";
FinAlgoritmo

Se ejecuta con el botón de reproducción. Y con el botón de diagrama de flujo ves el mismo algoritmo dibujado en cajas: es la mejor forma de entender qué es un ciclo.

4. Python y Google Colab: cero instalación

Python es el lenguaje de toda la carrera. Se eligió en Ciencias de Datos porque es legible (se parece al inglés), tiene librerías para estadística, gráficas y machine learning, y es el estándar de la industria.

Google Colab te deja escribir y ejecutar Python en el navegador, sin instalar nada, con tus archivos guardados en Google Drive. Para el primer semestre es todo lo que necesitas.

Cómo empezar: entra a Google Colab desde tu cuenta de Google (búscalo como "Google Colab"), crea un cuaderno nuevo, y renómbralo. Un cuaderno se compone de celdas:

  • Celdas de código: contienen Python y se ejecutan con Shift + Enter.
  • Celdas de texto: contienen Markdown, para tus explicaciones y apuntes.

Esa mezcla de código y texto es la razón por la que en ciencia de datos se trabaja en cuadernos y no en archivos sueltos: el análisis y su explicación viven juntos.

Regla de oro del cuaderno: ejecuta las celdas en orden. Si saltas una, las variables que definía no existen y el error que sale no tiene nada que ver con lo que estabas haciendo.

5. Variables y tipos

Una variable es un nombre que guarda un valor. Es la celda de Excel, pero con nombre propio en vez de B2.

Algoritmo Variables
    Definir contrato Como Caracter;
    Definir valor Como Real;
    Definir plazo Como Entero;
    Definir vigente Como Logico;

    contrato <- "089-2025";
    valor <- 26450538569.00;
    plazo <- 13;
    vigente <- Verdadero;

    Escribir "Contrato: ", contrato;
FinAlgoritmo

contrato = "089-2025"      # str  -> texto
valor = 26450538569.00     # float -> número con decimales
plazo = 13                 # int  -> número entero
vigente = True             # bool -> verdadero o falso

print("Contrato:", contrato)
print(type(valor))         # <class 'float'>

Los cuatro tipos básicos:

Tipo en Python Qué guarda Ejemplo
int enteros 13, -4, 0
float decimales 3.5, 0.19
str texto (entre comillas) "089-2025"
bool verdadero o falso True, False

Tres detalles que causan el 80 % de los errores del primer mes:

  1. El separador decimal en código es el punto, no la coma. 0.19, nunca 0,19. Escribir 0,19 no da error: crea dos valores distintos, y eso es peor que un error.
  2. = asigna, == compara. x = 5 guarda; x == 5 pregunta.
  3. "5" no es 5. El primero es texto y el segundo es número. "5" + "5" da "55", no 10. Se convierte con int() o float().

Nombres de variable: en minúsculas, sin tildes ni espacios, descriptivos. valor_total sí; vt no; Valor Total es error de sintaxis.

6. Entrada y salida

Algoritmo EntradaSalida
    Definir base Como Real;
    Escribir "Digite el valor base del contrato:";
    Leer base;
    Escribir "Usted digitó: ", base;
FinAlgoritmo

base = float(input("Digite el valor base del contrato: "))
print("Usted digitó:", base)

El detalle crítico: input() siempre devuelve texto, aunque escribas un número. Si necesitas operar, hay que convertir con int() o float(). Sin esa conversión, base * 2 te devuelve el texto repetido dos veces en vez del doble.

Formatear la salida con f-strings. Se pone una f antes de la comilla y las variables van entre llaves:

valor = 1234567.891
print(f"El valor es {valor:,.2f}")   # El valor es 1,234,567.89

Python usa por defecto la convención anglosajona (coma para miles, punto para decimales). Para el formato colombiano se intercambian:

texto = f"{1234567.891:,.2f}"
print(texto.replace(",", "@").replace(".", ",").replace("@", "."))
# 1.234.567,89

7. Operadores

Aritméticos

Operador Qué hace Ejemplo Resultado
+ - * suma, resta, producto 12 * 5 60
/ división (siempre decimal) 7 / 2 3.5
// división entera 7 // 2 3
% resto de la división 7 % 2 1
** potencia 2 ** 10 1024

El % parece exótico y no lo es: sirve para saber si un número es par (n % 2 == 0) o si algo es múltiplo de otra cosa. Aparece constantemente.

Relacionales: > < >= <= == !=. Devuelven True o False.

Lógicos: and (ambas), or (al menos una), not (niega). Son los Y, O y NO de Excel, y siguen las mismas leyes de De Morgan que viste en §14 del repaso de matemáticas.

print(5 > 3 and 2 > 4)   # False
print(5 > 3 or 2 > 4)    # True
print(not (5 > 3))       # False

8. Condicionales

Simple (solo hace algo si se cumple):

Si valor > 100000000 Entonces
    Escribir "Requiere aprobación adicional";
FinSi

if valor > 100000000:
    print("Requiere aprobación adicional")

Doble (dos caminos):

Si dias_restantes < 0 Entonces
    Escribir "Póliza VENCIDA";
SiNo
    Escribir "Póliza vigente";
FinSi

if dias_restantes < 0:
    print("Póliza VENCIDA")
else:
    print("Póliza vigente")

Anidado (tres o más caminos) — es el SI anidado de Excel, pero legible:

Si valor < 10000000 Entonces
    categoria <- "Menor";
SiNo
    Si valor < 100000000 Entonces
        categoria <- "Medio";
    SiNo
        categoria <- "Mayor";
    FinSi
FinSi

if valor < 10000000:
    categoria = "Menor"
elif valor < 100000000:
    categoria = "Medio"
else:
    categoria = "Mayor"

Compara las dos columnas: el pseudocódigo necesita anidar y cerrar dos FinSi; Python resuelve lo mismo plano con elif. Con cinco rangos la diferencia es abismal, y ahí es donde se ve por qué un SI anidado de Excel de cinco niveles es inmantenible.

La indentación en Python no es estética: es sintaxis. Los cuatro espacios que van antes de print son los que le dicen a Python "esto está dentro del if". Si los quitas, el programa cambia de significado o falla. En PSeInt eso lo hacen las palabras FinSi; en Python lo hace el espacio en blanco.

9. Ciclos

Un ciclo repite instrucciones. Es arrastrar la fórmula, pero diciendo cuántas filas.

Mientras / while — cuando no sabes cuántas veces, solo la condición de parada:

Mientras saldo > 0 Hacer
    saldo <- saldo - 30;
FinMientras

saldo = 100
while saldo > 0:
    saldo = saldo - 30
print("Saldo final:", saldo)   # -20

Para / for — cuando sabes exactamente cuántas veces:

Para i <- 1 Hasta 10 Con Paso 1 Hacer
    Escribir 7, " x ", i, " = ", 7*i;
FinPara

for i in range(1, 11):
    print(f"7 x {i} = {7*i}")

Ojo con range(1, 11): el límite superior no se incluye, así que range(1, 11) va de 1 a 10. Es la fuente número uno de errores "por uno" en todos los lenguajes.

Recorrer una lista directamente (lo más frecuente en ciencia de datos):

facturas = [1200000, 3400500, 780000, 15600000]
for f in facturas:
    print(f)

Cuidado con el ciclo infinito. Si la condición del while nunca se vuelve falsa, el programa no para. En Colab se detiene con el botón de parada de la celda. Provócalo una vez a propósito el día 16: entenderlo de golpe vale más que leerlo tres veces.

10. Contadores y acumuladores

Son los dos patrones más útiles que existen, y ya los conoces con otro nombre.

  • Contador: cuenta cuántos elementos cumplen algo. Es CONTAR.SI. Se inicializa en 0 y crece de uno en uno.
  • Acumulador: suma valores. Es SUMAR.SI. Se inicializa en 0 y crece con el valor.
contador <- 0;
acumulado <- 0;
Para i <- 1 Hasta n Con Paso 1 Hacer
    Si valores[i] > umbral Entonces
        contador <- contador + 1;
        acumulado <- acumulado + valores[i];
    FinSi
FinPara

valores = [4500000, 12000000, 8000000, 25000000, 300000]
umbral = 10000000
contador = 0
acumulado = 0

for v in valores:
    if v > umbral:
        contador = contador + 1
        acumulado = acumulado + v

print(f"Superan el umbral: {contador}")   # 2
print(f"Suma de esos: {acumulado}")       # 37000000

El error clásico: inicializar el contador dentro del ciclo. Si contador = 0 va adentro, se reinicia en cada vuelta y el resultado siempre es 0 o 1. Cuando un conteo dé 1, revisa primero eso.

contador = contador + 1 se abrevia contador += 1. Significa exactamente lo mismo.

11. Diez mini-retos con solución comentada

Intenta cada uno antes de mirar la solución. Un reto intentado y fallado enseña más que tres soluciones leídas.

Reto 1 — Tu primer programa

Pide un nombre y saluda.

nombre = input("¿Cómo te llamas? ")
print(f"Hola, {nombre}. Este es tu primer programa.")

Reto 2 — Las siete operaciones

Lee dos enteros y muestra suma, resta, producto, división, división entera, resto y potencia.

a = int(input("Primer número: "))
b = int(input("Segundo número: "))

print(f"Suma:            {a + b}")
print(f"Resta:           {a - b}")
print(f"Producto:        {a * b}")
print(f"División:        {a / b:.2f}")   # :.2f = dos decimales
print(f"División entera: {a // b}")
print(f"Resto:           {a % b}")
print(f"Potencia:        {a ** b}")

Con a = 12 y b = 5: 17, 7, 60, 2.40, 2, 2, 248832.

Reto 3 — Valor de un contrato con IVA

Dada una base gravable, calcular IVA del 19 % y valor total.

Algoritmo ValorConIVA
    Definir base, iva, total Como Real;
    Escribir "Digite la base gravable:";
    Leer base;
    iva <- base * 0.19;
    total <- base + iva;
    Escribir "IVA: ", iva;
    Escribir "Total: ", total;
FinAlgoritmo

base = float(input("Digite la base gravable: "))
TARIFA_IVA = 0.19          # constante: en MAYÚSCULAS por convención

iva = base * TARIFA_IVA
total = base + iva

print(f"IVA:   {iva:,.2f}")
print(f"Total: {total:,.2f}")
# Con base = 1000000 -> IVA 190,000.00 y total 1,190,000.00

Reto 4 — Base gravable a partir del total

El inverso del anterior, y el que más se equivoca en la vida real: se divide entre 1,19; no se resta el 19 %.

total = float(input("Valor total con IVA incluido: "))
base = total / 1.19
iva = total - base

print(f"Base gravable: {base:,.2f}")
print(f"IVA:           {iva:,.2f}")
# Con total = 297500 -> base 250,000.00 e IVA 47,500.00
# (restar el 19% daría 240,975.00, que está mal)

Reto 5 — Clasificar un pago por rango

Menor si es inferior a 10 millones; Medio entre 10 y 100 millones; Mayor de ahí en adelante.

Si valor < 10000000 Entonces
    categoria <- "Menor";
SiNo
    Si valor < 100000000 Entonces
        categoria <- "Medio";
    SiNo
        categoria <- "Mayor";
    FinSi
FinSi

valor = float(input("Valor del pago: "))

if valor < 10_000_000:              # el _ es solo separador visual: 10_000_000 == 10000000
    categoria = "Menor"
elif valor < 100_000_000:
    categoria = "Medio"
else:
    categoria = "Mayor"

print(f"Categoría: {categoria}")

Por qué el orden importa: al llegar al elif ya sabes que el valor no es menor a 10 millones, así que basta preguntar por el límite superior. Si escribieras las condiciones al revés, todos los pagos caerían en la primera.

Reto 6 — ¿La garantía cumple el amparo mínimo?

El amparo de cumplimiento debe ser al menos el 20 % del valor del contrato.

valor_contrato = float(input("Valor del contrato: "))
valor_amparo = float(input("Valor asegurado del amparo: "))
PORCENTAJE_MINIMO = 0.20

exigido = valor_contrato * PORCENTAJE_MINIMO

if valor_amparo >= exigido:
    print(f"CUMPLE. Exigido {exigido:,.2f}, presentado {valor_amparo:,.2f}")
else:
    faltante = exigido - valor_amparo
    print(f"NO CUMPLE. Falta {faltante:,.2f}")

Con valor_contrato = 26450538569 el exigido es 5,290,107,713.80. Nota que el programa no decide nada normativo: el porcentaje se toma del anexo de condiciones del contrato y se le entrega al programa. El código automatiza el cálculo, nunca el criterio.

Reto 7 — Contar pólizas vencidas (contador con while)

Dada una lista de días restantes para el vencimiento (negativo = ya vencida), contar cuántas están vencidas.

i <- 1;
vencidas <- 0;
Mientras i <= n Hacer
    Si dias[i] < 0 Entonces
        vencidas <- vencidas + 1;
    FinSi
    i <- i + 1;
FinMientras
Escribir "Vencidas: ", vencidas;

dias = [30, -5, 12, -40, 0, 90, -1]

i = 0                       # las listas de Python empiezan en 0, no en 1
vencidas = 0

while i < len(dias):        # len() da la cantidad de elementos
    if dias[i] < 0:
        vencidas = vencidas + 1
    i = i + 1               # sin esta línea el ciclo es infinito

print("Pólizas vencidas:", vencidas)   # 3

Fíjate en el 0: la póliza que vence hoy no cuenta como vencida, porque la condición es estrictamente < 0. Decidir si el límite lleva < o <= es la mitad del trabajo de programar bien.

Reto 8 — Sumar un lote de facturas (acumulador con for)

facturas = [1200000, 3400500, 780000, 15600000]

total = 0
for f in facturas:
    total = total + f

promedio = total / len(facturas)

print(f"Cantidad:  {len(facturas)}")
print(f"Total:     {total:,}")           # 20,980,500
print(f"Promedio:  {promedio:,.2f}")     # 5,245,125.00

Python trae sum(facturas) y haría lo mismo en una línea. Se escribe el ciclo a mano porque el objetivo del día es entender el patrón, no obtener el número.

Reto 9 — Contador y acumulador a la vez

Contar cuántos valores superan un umbral y sumar solo esos.

valores = [4500000, 12000000, 8000000, 25000000, 300000]
umbral = 10_000_000

cuantos = 0
suma = 0

for v in valores:
    if v > umbral:
        cuantos += 1        # equivale a cuantos = cuantos + 1
        suma += v

print(f"Superan el umbral: {cuantos}")           # 2
print(f"Suma de los que superan: {suma:,}")      # 37,000,000

if cuantos > 0:
    print(f"Promedio de esos: {suma/cuantos:,.2f}")
else:
    print("Ninguno supera el umbral")

El if cuantos > 0 del final no es adorno: sin él, una lista donde ninguno supere el umbral produce una división por cero y el programa se cae. Anticipar el caso vacío es un hábito que se paga solo.

Reto 10 — Promedio con centinela (while que no sabe cuántas vueltas dará)

Se leen valores hasta que el usuario digite -1, y entonces se muestra el promedio.

suma <- 0;
cantidad <- 0;
Escribir "Digite un valor (-1 para terminar):";
Leer valor;
Mientras valor <> -1 Hacer
    suma <- suma + valor;
    cantidad <- cantidad + 1;
    Escribir "Digite un valor (-1 para terminar):";
    Leer valor;
FinMientras
Si cantidad > 0 Entonces
    Escribir "Promedio: ", suma / cantidad;
SiNo
    Escribir "No se ingresaron datos";
FinSi

suma = 0
cantidad = 0

valor = float(input("Digite un valor (-1 para terminar): "))

while valor != -1:
    suma += valor
    cantidad += 1
    valor = float(input("Digite un valor (-1 para terminar): "))

if cantidad > 0:
    print(f"Promedio: {suma/cantidad:.2f}")
else:
    print("No se ingresaron datos")

Con los valores 3, 8, 5 y luego -1, el promedio es 5.33.

El patrón que hay que ver aquí: la lectura aparece dos veces, una antes del ciclo y otra al final del cuerpo. Si solo la pones antes, el ciclo es infinito; si solo la pones adentro al principio, el centinela -1 entra en la suma. Este esqueleto se llama "lectura anticipada" y lo vas a reutilizar todo el semestre.

12. Cómo leer un error sin asustarse

Vas a ver muchos errores. Son información, no fracaso. Python te dice tres cosas: en qué línea, de qué tipo y qué encontró.

Mensaje Qué significa casi siempre
SyntaxError: invalid syntax Falta un : al final del if/for/while, o falta cerrar un paréntesis
IndentationError La indentación no es consistente. Usa siempre 4 espacios
NameError: name 'x' is not defined Escribiste mal el nombre, o no ejecutaste la celda que lo definía
TypeError: can only concatenate str Estás sumando texto con número. Falta int() o float()
ValueError: could not convert string to float Digitaste una coma decimal, o texto donde iba un número
ZeroDivisionError División entre cero: casi siempre un contador que quedó en 0
IndexError: list index out of range Pediste el elemento 5 de una lista de 4. Recuerda que empiezan en 0

Lee siempre la última línea del mensaje primero. Ahí está la causa; lo de arriba es el rastro de cómo se llegó hasta ella.
